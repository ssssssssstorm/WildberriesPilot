# MarketPlacePilot

MarketPlacePilot — интерактивное демо будущего AI-менеджера для продавцов Wildberries.

В Telegram пользователь проходит рабочую смену менеджера: видит очередь обращений, открывает задачи, проверяет предложенные действия и подтверждает безопасные шаги в симуляции. Это не бот с набором кнопок и не советчик: демо показывает операционный сценарий работы с вопросами, отзывами, диалогами покупателей и возвратами.

## Локальный запуск: long polling

Требуется Python 3.12.

```bash
python -m venv .venv
.\.venv\\Scripts\\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
python -m marketplacepilot
```

Для этого режима достаточно `TELEGRAM_BOT_TOKEN`. Укажите его только в локальном файле `.env`: файл не попадает в Git.

## Render: webhook-режим

Для Web Service используется [render.yaml](render.yaml). Render запускает `uvicorn`, а Telegram присылает обновления на
`POST /telegram/webhook`. Long polling и webhook одновременно не используются.

Задайте в Render вручную следующие переменные:

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_WEBHOOK_SECRET=
WEBHOOK_BASE_URL=https://<ваш-домен>.onrender.com
```

`TELEGRAM_WEBHOOK_SECRET` — случайная строка из латинских букв, цифр, `_` и `-`; она проверяется на каждом webhook-запросе.
`WEBHOOK_BASE_URL` не должен заканчиваться на `/`. `PORT` выдаёт Render автоматически. При старте приложение вызывает
`setWebhook` для адреса `{WEBHOOK_BASE_URL}/telegram/webhook` и не удаляет webhook при коротком рестарте.

Браузерные endpoints:

- `GET /` — статусная страница демо;
- `GET /healthz` — быстрый JSON `{"status":"ok","mode":"demo"}` без токенов и изменения данных.

Бесплатный Render Web Service засыпает без входящих запросов и использует временную файловую систему. Внешний мониторинг
может безопасно вызывать `GET https://<ваш-домен>/healthz` раз в 5–10 минут. SQLite-сессии сбросятся после перезапуска,
redeploy или остановки сервиса — для текущего демо это допустимо.

## Демо-режим

Интерфейс всегда помечает данные как «ДЕМО-РЕЖИМ · Искусственные данные». Все товары, обращения и действия синтетические; ответы подготавливает прозрачная сценарная логика, а не нейросеть. Отправка ответа, изменение статуса и работа с возвратами происходят только внутри симуляции.

В полной версии агент будет подключаться к конкретному магазину через официальный WB API и сможет использовать LLM для согласованных сценариев. Рискованные действия, включая решения по возвратам, должны оставаться под подтверждением человека.
